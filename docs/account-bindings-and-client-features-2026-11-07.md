# 账户绑定与客户端功能扩展

协议更新为 **1.0.9**。服务端与网页必须一起更新；本轮没有部署打包、提交或推送。

## 账户绑定

账户面板显示 Discord、QQ 和邮箱。平台未配置时显示“暂未开放”，按钮禁用；按照用户要求，Discord／QQ 参数默认全部留空。邮箱是否可用由既有邮件配置决定，配置齐全后可以在注册登录后、进入游戏前绑定。

Discord／QQ 使用授权码流程，由服务器交换身份。绑定或解绑前验证当前游戏账户密码；提供方账户使用 `(provider, application, subject)` 唯一标识，不按昵称、QQ 号码或同名邮箱合并账户。每个游戏账户至多绑定一个 Discord 和一个 QQ 身份，已有绑定须先解绑再替换。邮箱继续使用验证码验证，要求强制邮箱的服务器不允许解绑邮箱。

游戏账户新增稳定 `account_id` 和结构化外部身份记录。JSON 持久化 `identity` 字段；MySQL 新增 `account_identity_state` 与 `account_external_identities` 表。外部身份在内存及数据库中均有唯一性约束。旧账户首次升级补充内部 ID，并保留原有 Unique 迁移的失败不改原文件契约。沙盒与 NPC 临时背包不复制登录身份或绑定记录。部署前应沿用账号库备份流程；旧版 JSON 保存器不认识新的身份字段，回退程序时应配套恢复升级前数据。

`CServer` 唯一持有 `CAccountLinkService`。工作线程仅接收值数据；提交前检查原会话、稳定账户 ID、密码摘要及一次性授权任务，成功回执等待保存代数落盘。当前限制为 32 个在途账户任务、128 个授权等待任务及128个待回执；授权任务五分钟有效。登出取消相关任务，关闭服务或热重载会停止并等待工作线程，未完成的授权需重新发起。

Web 桥接只提供固定回调页面，负责把授权码送回同源客户端；密钥、令牌交换均在 C++ 服务端。回调不反射查询参数到 HTML，不缓存页面，不发送 Referer。授权结果同时支持 opener 消息和同源 BroadcastChannel，客户端与服务端均校验绑定任务。

### 留空与启用配置

示例文件为 `deploy/windows/account_links.ps1.example`，所有值保持空字符串。以后复制为同目录的 `account_links.ps1`，填写后在启动服务端的同一 PowerShell 会话中点入，再启动服务端；使用启动器时也要重启启动器，让新进程继承环境变量。实际配置副本已被 Git 忽略，打包脚本也会排除它。

| 平台 | 环境变量 |
|---|---|
| Discord | `FLORRBT_DISCORD_CLIENT_ID`、`FLORRBT_DISCORD_CLIENT_SECRET`、`FLORRBT_DISCORD_REDIRECT_URI` |
| QQ | `FLORRBT_QQ_APP_ID`、`FLORRBT_QQ_APP_KEY`、`FLORRBT_QQ_REDIRECT_URI` |

回调地址分别为 `https://你的域名/oauth/callback/discord` 和 `https://你的域名/oauth/callback/qq`，必须与平台应用配置一致。反向代理需要将这些路径交给 Web 桥接。开发配置允许 localhost 回调，公开部署使用 HTTPS。

邮箱沿用 `email_enabled`、`email_username`、`email_password` 和 SMTP 配置；`email_enabled 1` 表示登录后可选绑定，`2` 表示强制绑定。测试没有向真实邮箱发信，也没有调用真实 Discord／QQ 应用。真实平台联调仍需应用参数及平台审核条件就绪。

## 功能扩展

新增 `CInventoryExtension`、`CTalentExtension` 和 `CCraftExtension`，由现有 `CExtensionRuntime` 唯一持有，世界继续使用非拥有视图。扩展负责功能描述、操作入口与权限编排，账户库存、天赋效果和经济回执仍由业务层持有。

`IClientFeatureExtension` 声明稳定功能键及描述，包含逻辑展示区域、交互类型、排序、图标/翻译键、角标支持、可见性、权限和不可用原因。区域位值为快捷栏 1、顶部栏 2、账户菜单 4、HUD 8；本轮三个功能均注册到快捷栏。客户端通过本地功能注册表选择已实现的界面，不加载服务器提供的脚本。

客户端权限分为查看 1、编辑/合成 2、锻造 4。可见性与权限独立：隐藏快捷按钮仍可以通过获准的快捷键打开功能；只读允许查看，禁止修改；禁用会关闭已打开的面板，按钮显示不可用原因。正常玩家请求在服务端复查权限，伪造客户端按钮状态不能绕过。

控制台或授权 RCON 可以配置世界策略：

```text
world_feature 0 craft hide
world_feature 0 craft show
world_feature 0 inventory readonly
world_feature 0 talent disable
world_feature 0 talent enable
world_feature 0 craft default
```

`default` 清除该项世界覆盖。策略进入世界快照；扩展作用域只校验自身生命周期配置，不重复持有一份权威功能策略。策略变化不卸载功能扩展，不清空物品、不撤销已有天赋，不取消已经提交的经济事务。

新增独立功能清单消息，携带玩家会话、世界实例、身体身份及修订号。初始化时纳入玩家基线，后续仅在内容变化时发送，不发送 Welcome、不重载地图。客户端拒绝过期、跨世界或身份不符的能力，身体切换后重新检查。

`player_feature_ui.js` 集中注册三个功能的按钮、面板与行为，原快捷键入口统一经过注册表。`client_features.js` 管理清单与权限。已有背包、合成、天赋渲染模块继续复用。

## 扩展运行时修复

- 全局扩展的玩家状态发布只执行一次，消除“全局遍历＋包含全局实例的世界视图”重复发布。
- 世界扩展集合变化时保留未移除的实例及状态，先验证并暂存新增实例，提交后只卸载被移除的实例。
- 功能键统一注册并检查重复，世界命令通过注册表识别功能，不硬编码三个名称。
- UI 策略变化走现有实例上的查询，不依赖重新构造扩展来刷新显示。
