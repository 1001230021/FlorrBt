## 进程内传输

举报和验证码邮件共用 `remote_transport`，参数与结果均为值；业务线程仍只在完成队列回填阶段访问玩家。取消令牌中断当前请求，举报取消还保留原有会话/epoch 校验；邮件关闭时清空待发队列并等待工作线程退出。

- 举报不再启动 shell/curl 进程，也不再落盘请求和回复。总请求期限仍为六秒，连接期限三秒；最多接受 256 KiB 回复。只有 HTTP 2xx 可以进入审核结果解析，不跟随重定向。
- 邮件正文和 SMTP 凭据留在内存中。保留 SMTPS 与强制 STARTTLS，证书链和主机名校验开启；服务端拒绝 STARTTLS 时不发送账号密码或正文。
- 取消、超时、响应过大、HTTP 状态、协议及资源错误有明确结果。日志不包含 URL、密钥、密码或回复正文，异常兜底也不直接输出可能携带敏感参数的 exception 文本。
- 删除 `email_curl_path` 配置；旧配置应移除该行，不再需要系统 curl.exe。
- 举报 JSON 的禁言时长必须为合法数值；保留纯数字回复兼容。旧实现搜索第一个数字，会把 `-60` 误读成正数，现已拒绝该类回复并使用关键词兜底。

依赖固定为 [curl 8.23.0](https://curl.se/download/curl-8.23.0.tar.xz)，通过 SHA256 校验：
`8dadd7d2536a314f982ad05a651b713f426bf7d02cc2c76cffb9796f2218e6c5`。
构建只需要 HTTP(S)/SMTP(S)，禁用其他文件传输协议。Windows 使用 Schannel 系统证书库，Linux 使用 OpenSSL。Windows 发布包携带 libcurl.dll 及许可文件；Linux 将 libcurl 静态链接到服务器，OpenSSL 仍按系统依赖链接。

CMake 首次配置下载依赖，需联网；离线构建可指定 `FETCHCONTENT_SOURCE_DIR_CURL` 为已准备的对应版本源码。原生 VS 项目通过 `tools/build_curl_sdk.ps1` 构建同一依赖，离线目录使用 `FLORRBT_CURL_SOURCE_DIR` 环境变量。没有把编译产物或下载源码加入仓库。

## 进程退出

`CServer::Init()` 明确返回是否初始化成功。main 只在成功时进入 Run，失败后仍走 Shutdown。内容注册、世界配置、扩展、持久化、模块初始化和就绪文件失败都返回非零退出码。

运行期 Tick 异常、非法固定 dt、关闭时持久化失败也设置非零退出码。普通退出保持 0，热重载退出码 42 和快照恢复失败码 43 保留；关闭持久化失败会取消原计划的 42，避免把数据保存失败当作可以重启。世界模块借用指针只在世界校验成功后绑定。
