## 1. 可拒绝阶段与已提交阶段分离

普通跨世界迁移和管理端控制权切换统一进入 `CWorldTransfer`。

1. 收集并校验结构性依赖、控制权、世界身份、目标坐标和可分配身份空间。
2. 控制器通过 `ValidatePlayerTransition(const SPlayerTransitionView&, side, error) const` 只读预检。
   参数只有复制的身份、位置、实体数量等值，不提供可变世界/玩家/实体指针。
3. 预先保存源/目标世界的索引与分配器检查点，然后预留所有目标 ID。
4. 暂存实体搬迁。原始对象不析构、不重新生成；失败时将原对象移回并恢复位置、前一位置、
   空间网格、实体/大实体/清理/更新索引、空闲 ID 和 generation 高水位。
5. 全组入库成功后重映射结构引用、提交玩家控制权，再执行后续清理和通知。

失败路径不运行队伍解散、装备恢复、技能取消、会话切换或网络通知。预留资源会被撤销。
目标点选择消耗的 RNG 在被拒绝时也恢复。回滚不使用全服热重载，不断开连接，也不替换原始实体对象。
同世界传送也通过同一依赖收集与位置/空间索引回滚路径，整组保持相对位置。

旧 `OnPlayerEnteredWorld` / `OnPlayerLeftWorld` 已移除，改为明确的提交后通知：

- `OnPlayerDepartureCommitted(world, player, departing_entity)`：明确传入离开的旧控制对象，
  控制权切换时不会误把旧世界装备规则应用到新控制对象。
- `OnPlayerArrivalCommitted(world, player)`。
- 实体使用 `OnWorldTransferCommitted()` 取消源世界空间动作，保留冷却及剩余附着弹药。

返回 `SPlayerTransitionResult`，包含 `committed`、合格的实体 handle 和错误信息，不返回可能失效的裸指针。
提交后的死亡/销毁属于后续游戏事件：结果仍是 committed，句柄可为空；不能把已执行的提交伪装成拒绝。

### 回调契约

所有可以拒绝迁移的条件必须放在只读预检。提交后通知不具备否决权；不能在那里返回一个失败要求撤销已发出的消息或已完成的游戏事件。
预检拒绝/异常和搬迁阶段异常走无副作用拒绝或检查点回滚。提交后通知中的程序异常沿服务器已有致命 tick 异常路径停止运行，
不宣称可以回滚任意 C++ 回调、外部 I/O 或进程崩溃。

事务期间阻止参与者再次迁移/更换控制权、被踢出、所属世界被删除/替换、控制器与上下文被更换，
也禁止捕获半提交快照。空间查询迭代过程中不进行迁移。主世界选择与拓扑恢复同样检查活动事务。

## 2. 复合实体整体迁移

`CollectTransferDependencies` 声明结构性依赖，`RemapTransferredReferences` 在提交时重写现存句柄。
已删除 `CanTransferBetweenWorlds` 的临时拒绝迁移机制。

- 控制根或任意身体节段时，根和全部节段一起迁移。
- 检查根/身体双向关系以及节段链接是否属于同一组件；无效结构整体拒绝，不静默丢成员。
- 另一个玩家控制了组内成员时整体拒绝，避免隐式迁移其他玩家。
- 所有附着弹药随拥有者迁移，更新 owner、Hornet 已装填引用、蒲公英一次性弹药数组。
- 保留弹药血量、寿命和已消耗数量，不补满一次性弹药，也不重复收取 Hornet 装填冷却。
- 更新根/节段/相邻节段引用以及状态 owner；毒素施加者和封槽状态的实体引用也按组重映射。
- 全组平移保持相对位置，入场规则改变阵营后同步结构成员的队伍。

非结构性关系仍采用原玩法规则：已发射弹体、独立召唤物在原世界清理，外部抓取关系释放，跨世界链断开，
花瓣按原规则重装。花瓣所有权先重绑定以使清理回调找到正确 flower；Relic 的源世界区域效果显式清理。
这不是把被攻击目标、所有邻近实体或整张世界关系图自动带走。

## 3. 主世界按标识解析

- `IGameWorldResolver` 增加 `GetMainWorld()`；`CGameContext::MainWorld()` 每次解析当前主世界。
- 网络模块不再持有 `CGameWorld& m_lobby_world`，上下文不再持有 `CGameWorld& m_world`。
- 登录、重连、重生、Welcome 与管理命令都获取当前主世界，并处理不存在的情况。
- `IWorldModule::SetMainWorld(id)` 原子选择已有的非房间世界；管理命令为 `world_main <world_id>`。
- 当前主世界仍不能直接删除。先选定另一主世界，再删除旧世界；旧世界玩家按正常迁移/重生规则处理。
- 热重载可恢复不同主世界 ID，或以不同地图重建该实例；网络和上下文不再要求旧对象地址存活。
  新地图加载和拓扑校验在丢弃旧世界前完成，后续语义失败沿现有热重载回退流程处理。
- 房间不能占用主世界的原有所有权规则保留，避免房间回收删除主世界。

网络协议仍为 `1.0.4`，快照容器仍为版本 2。没有部署、提交或推送。
