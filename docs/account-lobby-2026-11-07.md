# 账户预登录与背包驱动的开始页

## 流程

1. 客户端启动后，有有效的本地恢复凭据就发送 `AccountLogin`；缺少凭据时显示登录表单，验证失败时返回表单。
2. 服务端认证 CPlayer 并发送 `AuthResult`、绑定信息及 `Inventory`。此时没有控制实体、世界归属或待复活标记，不发送 Welcome 或实体快照。
3. 客户端只有在会话认证成功且收到相应账户的背包后才显示、允许使用“开始游戏”。本地保存过账户名不能跳过这两个条件。
4. 点击开始发送 `EnterGame`，服务端生成角色，或恢复此前断线留下的角色，再发送场景和身体基线。

开始页断线重连使用 AccountLogin，继续停留在开始页；已经进入游戏后的短暂断线沿用原有角色恢复流程。刷新页面会重新进入账户预登录。

旧 Login/Register 直入模式仍供兼容工具使用。新版 Web 的自动预登录不走这条路径。

## 背景花瓣

- 删除固定的演示花瓣列表，使用服务端 Inventory 中各 `(petalType, rarity)` 的数量。
- 后续根据原视频重新实现为持续生成：每次出生按数量权重取样，从左侧进入、向右离场；最多保留 64 个，不再预填固定装饰位。
- 每颗花瓣有独立的移动速度、角速度和轻摆相位；离场后移除，后续生成新的花瓣。
- 空背包、未登录、背包尚未同步时只显示草地；切换会话时清除旧分布及装饰位图。
- 稀有度随物品身份保留，不给高稀有度额外数量权重。

`menu_inventory.js` 管理数量与加权取样，`menu_petal_motion.js` 管理生成和运动，`menu_backdrop.js` 管理资源与绘制，均不创建世界实体。

## 同时修正

- 旧的 Chores/agree 复活请求可以在未入场时生成身体，现只允许已有身体或确实待复活的玩家使用。
- 账户登录的认证结果或背包入队失败会终止该连接，避免客户端永久等待缺失的登录基线。
- 无身体的账户状态查询只返回背包。
- 自动登录的凭据失效或地址异常时恢复登录表单。
- 从账户面板手动注册/登录后关闭表单，显示就绪开始页。
