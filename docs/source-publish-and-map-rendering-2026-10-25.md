# 源码清理与地图渲染修正

## 地图

缓存图块不再分别取整其贴图坐标和尺寸。贴图使用统一的世界到屏幕变换，只有像素归属的裁剪边界取整；完整采样边缘保留下来。直接绘制回退同样使用统一映射，并恢复画布状态，避免它留下的透明度再次乘到后续缓存图块上。

右上角地图切换使用单个连续插值的画面，卡片尺寸、位置、视野、标记和点击区域同步。连续点击会从当前过渡状态反向运动；换图清除旧过渡。

验证：33 个 Node 回归脚本通过；152 组实际 Canvas 像素比较通过，覆盖移动、缩放、DPI、透明图层、旧缓存和直接绘制回退。原生 Windows Debug 服务端及 EngineShared 构建通过。此次没有修改服务器游戏逻辑；上轮的 77/77 运行时及 90/90 标准测试结果见密道说明。

- 原生工程的 SDK 路径改为共享属性表和忽略的 `FlorrBt.Dependencies.local.props`；提供 `FlorrBt.Dependencies.example.props`。
- 增加 `tools/check_source_hygiene.mjs` 和 CI 检查，阻止常见账号数据、运行配置、日志、缓存、构建产物和可识别密钥进入源码。
- 保留游戏实际使用的字体、音频、地图、图片、第三方源码和回归测试。
- 历史中曾出现非空 `data/accounts.json`。清理当前目录不会删除旧提交；历史改写单独准备，不以普通源码推送代替历史清理。
