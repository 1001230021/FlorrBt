## 使用与实现范围

启动原来的 FBT 服务端和 `node tools/web_client_server.js`，打开：

`http://127.0.0.1:8080/reference.html`

并排比较：`http://127.0.0.1:8080/reference/compare.html`，左侧打开本地视频（不上传），右侧是可交互的参考客户端；支持视频慢放。

登录、注册、恢复凭据、快照与 ACK、场景切换、移动/攻防、拾取、换装、合成、天赋、图鉴、聊天、队伍、死亡/复活使用现有客户端实现与真实 1.0.7 协议。
本次没有模拟正式背包余额、合成概率或击杀结果。参考入口读取当前 HTML 的 DOM 模板，并挂载同一套游戏模块，避免抄出第二套协议。

入口和设置是独立的，`florrbt.reference.settings` 不改原客户端的显示偏好。账号和服务器无需迁移。
FBT 服务端可以生成不同数量的花瓣槽；参考布局保留真实槽位，不画出假的十槽。

还原内容：

- 左侧三色面板、黄色图鉴、灰色设置、左上头像与条形状态、右上小地图、底部双排卡片。
- 在参考分辨率下，背包 404×604、合成 612×698、天赋 654×654、图鉴 600×604；所有尺寸随现有布局系统缩放。
- 卡片名称按卡宽约16%封顶，数量角标旋转，保留真实卡片稀有度与素材。
- 五卡合成轨道、返回卡片和成功结果沿用现有权威结果动画；打开界面不会创建第二个动画主循环。
- 天赋树初始视距缩小，保留 FBT 的前置关系、价格与真实学习请求。
- 默认世界视距使用服务端可见范围的67%，使基础花朵尺寸更接近视频；玩家仍可滚轮调整。

无法宣称逐像素完全一致：FBT 地图、服务器数值、花瓣集合及天赋拓扑与视频不同。视频成就条、未实现的系统按钮、Shell/Sponge 等缺少对应服务端内容的项目不伪造；所有 FBT 稀有度保留，面板超出参考列数时可横向滚动。多人队伍及特殊生物的原有实现被复用，本轮专项验收范围见下文。

## 联网检查时修复的实际问题

1. CMake 静态库只包含自动注册、没有外部引用的 `commands.cpp` 被链接器丢弃。独立启动时出现 `Unknown command set`，全部启动配置失效。现在服务器和运行时测试直接链接该编译单元；原生 VS 本来直接编译，不受影响。
2. HTTPS 页面默认仍生成 `ws://`，浏览器会阻止混合内容。新增 `defaultSocketEndpoint`，HTTPS 默认 `wss://`，HTTP 仍用 `ws://`。
3. 参考启动器在模块初始化后发布 DOM 就绪标志，测试及外部启动页不会在设置尚未读取时抢先填写登录表单。

还定位了一个跨层问题：RCON `equip` 只修改生物实体槽位，没有同步账户装备账本；之后正常整套换装会触发 `CPlayer::TryApplyLoadout` 的 `WrongScope` 保护。测试已改为通过真实 UI 装备，不绕过这项保护。建议后续把“管理员修改玩家装备”和“修改 NPC 原型装备”拆成明确入口，前者必须使用库存事务；本次未擅自改变管理命令的物品生成语义。

## web 架构问题

以下判断来自当前源码和本轮真实浏览器，不把旧版已修复的问题重复列入。

### P1：启动、业务、网络、绘制仍在同一个生命周期中

位置：`web/src/game.js`（约10500行）、`app_context.js`、`ui_settings.js`、`ui_codex.js`。

`game.js` 导入即绑定 DOM、启动定时器、读取存储、加载字体/地图和注册网络处理。其他模块直接读写同一 `state`。依赖检查仍有 `{game.js, ui_codex.js, ui_settings.js}` 环。
更换 UI 时，即使只需要网络层，也必须带上整个页面。参考入口因此复用了 DOM 模板；这是参考版的具体取舍，不是长期模块边界。

建议先抽 `ClientSession`（连接、收包、快照历史、经济回执）和 `GameModel`（权威快照、预测、场景代数），再由 `mountGameUI({model,commands})` 挂载界面。组件统一返回 dispose；UI 不导入启动器。不要先做纯文件切割，却继续共享可变全局状态。

### P1：界面展示与服务端定义有多份事实

位置：`petal_info.js` 的花瓣数值分支、`talent_data.js`、`sim_entities.js` 的预测常量、`client_config.js`。

协议提供物品身份、技能结果和槽位状态，但图鉴说明、部分属性、天赋价格及移动预测仍有本地表。服务端热更新后，卡片文字和真实结算可能不一致；视觉复刻无法解决这个差异。

建议服务器公布带版本的内容描述/能力清单，按 hash 缓存；客户端只本地化文本及绘制图标。局部改动不下发全世界定义，预测保留已确认的输入参数。

### P1/P2：经济回执与乐观界面仍有第二套状态机

位置：`game.js::enqueueSlotTransaction`、`makeDisplaySlotState`、`handleCraftResult`，`economy_requests.js`、`craft_motion.js`。

请求已具有背包作用域、编号和持久化终态，这是优点；UI 又维护超时回退、显示库存、槽位事务和动画阶段。断线、换身体、迟到回执必须在多个位置同时撤销，容易出现数字先回退再跳动。

建议以不可变的 operation view 驱动显示，统一 pending/committed/rejected/unknown，动画只订阅终态；不能用动画结束推断经济成功。保留现有幂等协议。

### P2：几何、样式和绘制尺寸多处重复

位置：`styles.css`（约3700行）、`layout.css`、`mobile.css`、`ui_layout.js`，以及 Canvas HUD。

同一面板尺寸、边框、字体先有基础规则，再被桌面、移动端、运行时 CSS 变量覆盖。视频复刻时，调小 DOM 卡片不会自动修正 Canvas 文字或天赋初始相机。

建议把颜色、卡片度量、描边、面板原点和动画时间提成一个表现配置；CSS 与 Canvas 消费同一组 token。最终将默认主题和参考主题对同一内容做截图回归，避免继续添加高优先级覆盖。

### P2：生命周期不能整体卸载

位置：`net_messages.js` 注册表、`game.js` 的事件和 setInterval、`ui_talents.js` 的观察者、资源缓存。

普通整页刷新可由浏览器回收；但单页切换客户端或重新挂载没有明确的 dispose 边界。重复注册会报错，监听器/动画回调也可能继续引用旧 DOM。

建议让 session、scene、panel 分别有 dispose，事件用 AbortSignal，断线只清会话，场景切换只清场景；避免全局 reset 清错层级。

## 性能与优化问题

### 初次地图和资源准备有主线程尖峰

位置：`map_renderer.js::loadMapData`、`game.js::scheduleBackgroundAssetWarmup`、`prepareFrameRenderCaches`。

本轮早期真实联网运行中，冻结监测记录了约1.1～1.3秒主线程停顿；这发生在场景/资源准备阶段，不能仅凭总时长归因于某一个函数。
后台预热同时触发清单下载、多个物种解析、花瓣 SVG 衍生和纹理准备。部分工作并不受 `preloadAssets({concurrency:8})` 的单个队列约束。

建议把地图碰撞/索引解析放 worker，图片解码和首次栅格化使用统一时间预算；优先本视野、当前装备和已打开面板，随后预热邻区。用 Performance trace 拆分 JSON解析、DOMParser、decode、栅格化各段，再定预算。

### 缓存有预算，但总占用尚未统一

位置：`raster_budget.js`、`render_text.js`、`visual_assets.js`、`petal_info.js`。

地图/精灵有共享预算，文字另有48MiB预算；源 SVG 文本、成功 Blob URL、DOM 卡片和原始图片又使用整页缓存。不能把一个 raster budget 当作整个客户端内存上限。

建议区分长期源资源与场景/皮肤/尺寸衍生资源，给后者引用计数与预算。用户切语言、缩放、反复切图时采集总堆和纹理占用，而非只看 Map.size。

本轮网络检查另发现现有 `EouPheromone` 图标映射请求不存在的 `assets/petals/eou_pheromone.svg`。生成器同步 ID 不能保证素材存在；应加入“所有展示 ID 能找到资源或显式回退”的内容契约检查。该 FBT 专属图标不属于本次视频共有内容，报告保留待补资源项。

### 文本缓存键没有完整字体身份

位置：`render_text.js::outlinedTextRaster`。键包含字号桶、颜色、粗细前缀和文本，但没有字号后面的字体族；相同文本使用不同字体族时可能复用错误栅格。

建议键包含规范化 font 完整描述以及字体加载代数；字体异步就绪时只失效相关条目。当前多数调用字体族相同，不能把风险描述为每帧必现。

### 卡片列表和派生列表仍有重复工作

位置：`game.js::renderInventoryGroups`、`makeDisplaySlotState`、`ui_codex.js::renderCodexPanel`。

合成矩阵已有 IntersectionObserver 和分批创建，是值得保留的优化；背包仍在变更时构造全组签名及节点，图鉴处理完整类型×稀有度网格。大背包会把 SVG、监听器和 DOM 布局成本叠在一起。

建议按库存 revision 更新变更行，使用虚拟行保留可见区及少量预取；拖动中的卡片由独立 overlay 持有。排序、过滤和数量格式缓存按 revision/locale 失效，不每帧计算。

### 快照与预测成本要按实体规模测量

位置：`game.js::resolveSnapshot`（最多90份历史）、`sim_entities.js`、`scene_passes.js`。

当前有差量、ID代数、可见性裁剪和分层绘制，不应直接推倒重写。需要测100/500/1000实体下的解码、Map复制、预测、收集、绘制成本与分配量，确认瓶颈后再考虑结构化数组或worker；不要仅凭 `Map` 或 `dynamic` 就判为慢。
