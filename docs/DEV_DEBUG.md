# Dev Debug 世界工作台

## 进入

重新编译服务端，**重启网页桥接服务**（`tools/web_client_server.js`），并刷新网页客户端。按 F1：

```text
rcon <你的 RCON 密码>
dev_debug
```

`dev` 是客户端别名；授权后也可输入 `rcon dev_debug`。
服务端未设置密码时，需先在**服务端控制台**用 `rcon_keyboard <密码>` 设置。
调试控制台内直接输入服务端命令，不加 `rcon` 前缀。新协议不重发 RCON 密码，
票据不写入 URL、localStorage 或调试命令历史。手动输入的管理命令和原控制台输出
仍可能含敏感设置，请勿将调试控制台共享给非管理员。

## 交互

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 围绕光标缩放 |
| 中键拖动 | 平移观察视角，停止跟随 |
| 左键 | 选择实体并查看 ID、代次、位置、状态和属性 |
| 左键拖框 | 选择框内实体的中心；长按后显示矩形预览 |
| Shift + 左键 | 从组中增加／移除一只；Shift 框选追加 |
| 右键已选实体 | 操作整个待操作组 |
| 右键其他地图位置 | 记录坐标，生成生物／花瓣掉落，移动待操作组 |
| 玩家列表左键／右键 | 详情／管理菜单；双击定位并跟随 |
| F1 | 聚焦工作台服务端控制台 |
| Escape | 依次关闭类型选择、表单、菜单，或清空选择 |
| 返回游戏 | 关闭观察者连接，恢复原游戏输入与视图 |

工具栏可筛选生物、花瓣／掉落或全部实体，并显示隐藏实体、ID。
玩家按同世界优先、名字字母排序。玩家详情包含账号名、IP、连接情况、
等级、经验、背包、主副槽、天赋、图鉴、检查点，以及当前实体属性。
类型选择器来自**服务端已注册目录**，兼容额外类型；稀有度在独立控件选择。

## 管理操作

- 实体／组：恢复生命、设置阵营、保持相对位置移动、正常伤害击杀、无击杀奖励移除。
- 坐标：生成指定 type／rarity 的生物或花瓣掉落，一次最多 64 个。
- 玩家：定位、恢复生命、击杀、传送、禁言／解禁、踢出、背包数量增删改。
- 控制台：现有服务端命令、实时 CLogger 日志、命令名补全和内存内历史。

新增服务端命令（原有 `add` 等不变）：

```text
inventory <玩家名或ID> list
inventory <玩家名或ID> add <petal名称或ID> <rarity名称或ID> <数量>
inventory <玩家名或ID> remove <petal名称或ID> <rarity名称或ID> <数量>
inventory <玩家名或ID> set <petal名称或ID> <rarity名称或ID> <数量>
```

背包只改“可用库存”，不清空已装备主副槽，不强行覆盖 controller 的运行时槽。
沿用账号存储的保存批处理及 MySQL 后端；沙盒账号仍保持原有沙盒隔离语义。
`remove` 库存不足会拒绝；`set 0` 清除此种同品质的可用库存；数量上限 10 亿。

## 网络与安全边界

游戏端完成 RCON 授权后通过 `/dev_debug` 请求一次性票据；另开同地址 WebSocket，
首字节 `0xd0` 进入独立观察者协议。普通游戏连接继续使用 `0xfb` 版本握手。
网页桥接按客户端首帧固定通道类型：普通游戏保持原快照合并策略，调试帧完整透传，
不会用普通游戏的 16 位长度前缀拆包，也不会丢弃操作回复或把日志误当快照。
调试连接不创建 `CPlayer`、不占玩家 ID、不会生成花朵；原游戏连接保留作为授权来源。

安全约束：256 位随机、30 秒一次性票据，绑定授权玩家、账号、地址和当前 RCON 密码；
授权玩家断线、退出授权或密码变化即撤销。请求大小、频率、实体数、批量目标数、
日志和发送积压都有限额。实体引用携带世界 ID + 世界实例代次 + ID + 实体代次，不接受过期引用。
命令仅在服务器线程运行，菜单使用结构化参数，不拼接用户文字为管理命令。
所有菜单写操作审计；批量删除、击杀、背包覆盖先在界面确认。
玩家详情不包含密码、哈希、邮箱验证信息或其他认证凭据。

限制：最多 8 个已授权观察者；握手最多 512B、操作请求 32KiB、回复 2MiB、
积压 4MiB；请求平均 20 次/秒，命令最多 4 次/秒；快照约 10Hz、每视野最多 1024 个实体；
组最多 128 个。截断会在界面提示，放大视图或分批操作即可。
服务端日志保留最近 512 条，客户端显示最多 600 行，不在浏览器持久化。
大视野不会遍历海量空空间网格，而按实际实体数量收集，避免缩放拖垮 tick。

原游戏连接继续保留授权身份，但打开工作台后持续发送中性输入；不会新增玩家。
已有角色仍是正常游戏角色，不自动获得无敌、不暂停世界。观察不改变远区生物的休眠规则。
地形使用独立地图状态，读取地图文件并同步当前图块和后续墙体移除；切换世界会清除旧选择。
绘制复用游戏实体函数和贴图缓存，临时渲染状态通过 `try/finally` 恢复；背景 UI 暂时 inert。
日志订阅支持多线程注册／移除，移除会等待正在执行的回调，避免 GUI 退出时访问已销毁对象。
生产环境请使用 HTTPS/WSS 和可信的 TCP 代理网络，不要在不可信网络中裸传 RCON 登录。

## 地图加载失败排查

调试协议的 `map` 是显示名（例如 `garden`），`mapPath` 才是实际文件路径
（例如 `data/maps/garden.tmj`）。客户端优先加载 `mapPath`，并兼容旧服务端：
缺少扩展名时补 `.tmj`，不会再请求不存在的 `/data/maps/garden`。
路径变化会重新加载，即使两个地图的显示名相同。加载失败后点击工作台的“刷新”会重试。

本次路径修复的前端兼容部分只需强制刷新网页并重新进入工作台即可生效；
新的 `mapPath` 字段和刷新请求的成功回复需要重新编译并更新服务端。
网页桥接直接读取静态文件，此项前端修改无需重启桥接；修改桥接脚本本身仍需要重启。

若 `/data/maps/garden.tmj` 也返回 404，应检查当前桥接的 `FLORRBT_ROOT` 是否指向
包含 `web/`、`data/maps/` 和 `data/tiles/` 的同一个部署目录。地图还会加载相对引用的
`.tsj` 与贴图文件，部署时不能只复制 `.tmj`。

## 验证

```text
node tools/test_dev_debug.mjs
node tools/test_map_loading.mjs
node tools/check_client_deps.mjs
node --test tests/web_bridge/test_debug_forwarder.test.mjs
cmake -S tests -B build-tests
cmake --build build-tests --config Release
ctest --test-dir build-tests -C Release --output-on-failure
```

测试使用纯逻辑、模拟 DOM／socket，不启动游戏、服务端或数据库。
实机建议验证：未授权入口被拒绝 → 正常授权进入 → 两个世界来回切换 → 实体消失/ID 重用后批量操作被拒绝 →
修改一个测试账号的背包 → `rcon logout` / 原游戏断线后观察者连接关闭。
