# 死亡表现对齐

参考：`QQ20260925-113531-HD.mp4`，18.49s，约60fps。关键片段约15.7–18.4s。

## 录屏中能确认的差异

- 死亡发生时没有突然刹停，身体沿原来的运动方向继续滑行。
- 世界与怪物继续运动；镜头随后拉近，玩家尸体仍留在世界中。
- 中央提示与世界尸体不是同一个对象：提示内是更大的 X 眼花朵和死亡时的配装。
- 中央提示自上方滑入，内容是来源、配装展示、Continue、Close 两个纵向按钮。
- 本局收集位于右上，左上头像继续显示死亡表情。
- 录屏没有点击 Continue/Close，不能由此断言 florr 的复活协议或关闭后的完整流程。

## 实现

- `death_motion.js` 捕获死亡前的本地预测/快照速度，用解析指数衰减做最多0.8秒的视觉惯性。位移有上限，零速不产生位移，房间跳转不当作速度。
- FBT 原来每一条死亡快照都调用强制位置重置；现改为死亡展示独立推进，后续快照不重启动画。复活、欢迎包/切图重置和大幅位置跳转清理旧状态。
- 本地死亡视野系数平滑趋近0.6，复活后恢复1。不修改玩家保存的缩放参数，不扩大服务端快照范围。
- 死亡表情轻微倾斜，不再固定翻到180度。
- `death_portrait.js` 缓存死亡时的槽位/副本清单，绘制176px配装展示；与世界实体和实时换槽分开。
- Continue 保留 FBT 现有复活请求，仅防止连续点击发包；未收到确认时3秒后可重试。没有添加自动复活或修改复活规则。
- Close 收起中央提示并保留复活入口；右上收集栏仍可查看，库存消息到达时刷新。
- 伤害来源仍是已有服务端视觉伤害事件提供的最近来源，不伪称新增了精确击杀归因协议。
- 消失中的其他移动实体也继承短暂、有上限的视觉惯性；掉落卡保持此前的原地旋转缩小。

这一轮全部是客户端展示。没有改变死亡后碰撞、伤害、拾取、库存、天赋和服务器尸体坐标。

## 验证

离线检查覆盖30/60/120fps一致性、重复死亡快照、零速/高速/传送、复活清理、配装深拷贝、图片数量上限及Canvas调用。客户端语法、依赖、三语言、HTML/CSS和diff检查通过。没有启动游戏/浏览器实测；视频不能证明 florr 内部保存速度的具体方式，本次是可见行为的近似复刻。
