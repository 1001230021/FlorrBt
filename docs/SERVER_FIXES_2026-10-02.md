# 服务端修复与验证（2026-10-02）

对应 [本轮审查报告](SERVER_REVIEW_2026-10-02.md) 中确认的七项问题。本次同时处理了存档、刷怪归属和碰撞候选的重复开销；不改变贡献超时、图鉴计数这两项待确认的玩法规则。

## 七项修复

1. **伤害贡献**：`CDamageData` 保存账号名，不再保存 `CPlayer*`。结算时只解析当前已认证的相同账号；完全离线时安全跳过，同账号重连可以继续计入贡献。热重载直接保存账号字段，旧贡献记录仅在恢复旧快照时一次性解析其玩家记录。
2. **花瓣释放**：`CPetal::OnBeforeRemoved` 在对象释放前摘除所属槽引用、更新回装计时与属性。`NotifyCleared` 保证清理回调最多一次，正常卸载/重载/换世界也复用该入口；休眠花朵不必先恢复 Tick 才能清理。
3. **输入执行顺序**：移动与攻防各自保存已执行序号，到期的旧输入不能撤销较新的松手。支持 uint32 序号回绕；旧式未编号输入会为它修改的通道建立失效边界，不被较早的排程包覆盖。
4. **高速碰撞**：候选阶段使用双方上一位置到当前位置的 swept AABB，随后复用原线段/圆形精确检测。统一覆盖大小实体，每个无序对只进窄阶段一次。并非把所有 mob 改成连续伤害；额外压力轮次仍只传递速度，不重复造成伤害。
5. **合堆时间**：任一堆仍在惯性/禁止拾取阶段时不合并。合并成功使用双方较晚的过期时间，避免新数量随旧堆过期。这个选择会适度延长旧数量寿命，换取不损失新数量；总数和 uint16 stack 上限保持。
6. **私人掉落**：创建时绑定认证账号，显示、拾取和合堆都按账号校验，不再凭可复用的连接 ID。相同账号换连接 ID 仍可认领，不同账号不能继承。
7. **Corruption 与队伍**：旧 controller 离场处理完成后、目标 controller 分队前清除临时队伍覆盖；debug 改队也先撤销覆盖。状态析构只在仍然处于其覆盖队伍时恢复旧值，避免覆盖已经改好的新队伍。

## 兼容性与安全选择

- 网络协议未改变，不需要因为这些修复单独升级客户端版本号；先前 Bubble 的双标志修复仍需使用新版网页。
- 新热重载快照为伤害记录和掉落写入账号。**旧格式私人掉落仅有连接 ID，无法确认原始账号，恢复时保持不可见、不可拾取，直到原寿命到期**，不会将其转成公共掉落或送给复用 ID 的新账号。只影响旧快照中尚未拾取的私人地面掉落，不改库存、装备、账号或 Unique 持有记录。
- 普通公共掉落仍为公共掉落，未改变掉落概率、拾取半径或合成规则。
- 暂未更改120秒贡献超时和“有掉落才增加图鉴计数”的历史规则。

## 性能调整

### 保存与 MySQL

- 主线程用不可变账号快照复用未修改账号，后台从不读可变账号数据。可写查找会标记对应账号需要重新捕获；Load/Import 重置缓存，迁移工具仍兼容原 vector 接口。
- 一个服务器逻辑 tick 内的多次背包/经验变动合并为一次保存请求，在热重载 Flush 前结束批次。
- 每次仍会组装账号指针列表，但不再深拷贝所有账号的背包、天赋、图鉴。离线样例：1000个账号首次复制1000份，未改变再次保存复制0份，只改一个账号复制1份；已发给保存线程的旧版本不受后续修改影响。
- 保存线程复用自己的 MySQL 连接；重连后重新检查 schema。查询失败使连接退出复用，下一次重建连接，事务失败不推进已发布状态。
- items/talents/codex 按实际变动的分区写入：只改经验不重写三张子表，只改库存不删除天赋/图鉴。尚未细分到每个 inventory row，避免把本轮扩成数据库模型迁移。
- 完整快照、generation、Flush、删除账号和失败后再次保存的语义保留。SQL 错误消息不再回显可能包含账号认证字段的语句片段。

### 刷新与碰撞

- 区域多边形预计算边界框，先排除不可能更近的区域；同一生物未移动时复用区域结果。缓存包含实体代次，实体移除/换世界/恢复世界时清理，传送按新位置重新计算。
- 刷新抑制源用空间格缩小查询范围，极大范围走有界的备用列表；结果与原先逐个遍历的衰减公式一致。没有减少刷新尝试数或悄悄调整品质分布。
- 碰撞每 tick 构建一次实际 swept bounds，按 x 排序，用前缀最大边界检索；只以活动实体发起查询，排除休眠-休眠对。不再为每个小实体按固定200世界单位扩圈捞取候选。
- 保留质量权重、Wax 特殊响应、墙体约束、有效性复查和压力链轮数。没有声称已取得某个实机 TPS 提升，仍需大场景测量。
