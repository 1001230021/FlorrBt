## 部署与架构边界

1. **协议不兼容升级。** 客户端与服务器的版本均为 `1.0.4`，必须同时部署。旧客户端通过现有版本握手明确拒绝，并提示刷新。TCP/桥接的两字节包长度前缀不变。
2. **主世界仍被网络和游戏上下文直接引用。** 恢复保留主世界对象地址；主世界 ID 或地图不匹配时，在破坏性恢复前拒绝。任意替换主世界需要另行改造引用所有权，不能靠当前快照补丁完成。
3. **旧快照缺失的数据无法凭空恢复。** 没有 `world_topology` 的旧快照仍支持已有静态世界，但不能保证重建旧动态房间及其房间号。没有 `base_stats` 的旧记录只能使用原型默认属性，不能精确找回历史随机结果/生成时倍率。升级前应保留原程序、原快照，并结束旧动态房间或采用受控重启。
4. **恢复与重平衡不同。** 现存实体恢复其保存的基础属性；若希望配置变更立即重算所有既有实体，需要明确的属性迁移策略，而不是再次调用随机工厂。
5. **新快照不承诺向旧二进制降级。** Hornet runtime 已升级到版本 2；正常向前恢复提供旧动作迁移，回滚到更早二进制应使用该二进制生成的快照。
6. **跨世界迁移仍是单实体操作，不是整个关联对象图的事务。** 多节生物、蒲公英剩余一次性弹药已用拒绝迁移保护，不能视为完整支持。若要支持它们过门，需要先收集根/身体/弹药等归属对象、整体预留目标身份并重映射双向引用，验证失败时整体回退；技能、召唤物和已发射弹体还需明确各自的迁移规则。销毁源世界时无法迁移的玩家仍走显式回大厅重生流程。
7. **世界回调与控制权变更仍不是可回滚事务。** 本轮阻止同世界误退出，并在回调后重新验证身份；但若回调已解散团队、删除实体或切换会话，返回失败不代表这些副作用已经撤销。进一步改造需要区分“换控制对象”“退出世界”“加入世界”，以预检/提交阶段和明确的回调契约统一所有权，不能把任意回调当成没有副作用的通知。

运行时测试复用生产 `ServerCore`，不启动网络监听、GUI 或认证工作线程；账号与快照写入独立的 `artifacts/runtime-repairs-*` 目录。CMake 需要可用的 SFML 3 和 Jansson 开发库；用于无数据库验证时可设置 `FLORRBT_WITH_MYSQL=OFF`。Windows CTest 会为 SFML/TMJ 补齐运行库路径。

CI 已加入实体身份协议检查、标准 C++ 测试、无界面运行时回归，以及压测/天气工具的离线协议测试。旧的离线 Moon、轨道锚点、名称布局和伤害反馈测试也更新为当前行为，未回退游戏实现。
