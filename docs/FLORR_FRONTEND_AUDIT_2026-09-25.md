# florr 实机录屏与当前 FlorrBt 前端对照

参考：`QQ20260925-022649-HD.mp4`，约 11:46，1918×1028，约 60fps。

方法：全时段每 6 秒建立总览，再抽取换图、设置、天赋、战斗、聊天、死亡、合成的原分辨率帧；Flower 同时对照此前提供的 `Flower.cc`。比较基线是**当前工作区代码**，不是已经过时的 9/12 FBT 录屏。下文覆盖可从这段视频确认的表现类别，不声称逐像素重建了未展示的状态，或已取得 florr 的内部算法。

## Flower（本次重点）

| 可见差异 | FBT 原状 | 本次处理 |
|---|---|---|
| 世界花朵的黄色与外缘 | 偏暗黄，SVG 画布留白使可见半径变小 | 原生圆形路径；黄色填充与同色系深边；外缘与传入半径一致 |
| 左上头像和世界体色 | 同一 SVG / 滤镜路径 | 共用几何，头像独立较暗的黄色调 |
| 五官整体比例 | 绘制时又缩放为 0.86 | 删除额外缩放，使用 25 单位坐标体系 |
| 两眼间距 | 眼中心约 ±0.198R | 调整到 ±7/25R |
| 黑眼形状 | 偏窄、偏长 | 椭圆半轴 3×6，附细描边 |
| 眼内白色区域 | 很小的泛黄反光点 | 较大的纯白圆形，裁在黑眼内 |
| 视线 | 跟移动朝向，鼠标静止看不到独立反馈 | 本机跟随鼠标相对位置；远端依照服务端方向 |
| 表情转换 | 正常/攻击直接切换画法 | 嘴曲率、眉部遮罩、视线指数插值，独立于帧率 |
| 嘴的高度和形状 | 小弧线偏上、偏棕 | 深灰二次曲线，端点 `(±6,10)`，正常控制点 y=16 |
| 防御与攻击表情 | 同一皱眉嘴、攻击眼硬切 | 防御保留圆眼；攻击用滑入的 V 形眉部遮罩 |
| 死亡 | 随机瞬间角度，HUD 还参与实体放大淡出 | X 眼、皱眉，渐转半圈；HUD 保持固定尺寸与可见性 |
| 天线 | 贴图放大倍率与额外偏移，外展过宽 | 改成两根靠近头顶的黑色渐细曲线 |
| Disc 外观 | 无独立身体黑边反馈 | 已装备时使用较粗黑色身体边缘 |
| 中毒/失疗染色 | 多个 Canvas filter 叠加 | 直接选择填充/边缘颜色；中毒紫、失疗浅色等状态仍保留 |
| 受击 | 白色覆盖 | 花朵直接混合暖红色，不创建滤镜中间表面 |
| 绘制一致性 | SVG/fallback/脸部独立，比例不统一 | 世界、自己头像、队友头像共享 `flower_renderer.js` |

观察点：2:06、2:39、3:00、7:50、7:54、10:00、10:52。世界主体在本片大部分时候较小，HUD 的眼睛/嘴可作较清晰的参考。压缩、游戏亮度/天气会改变像素颜色；没有宣称 RGB 与每个像素绝对相同。第三眼、斗笠、绷带仍使用已有资产；本片没有给出足够清晰的所有装备/皮肤组合。

## 战斗、移动、掉落

| 可见差异 | 原状 | 本次处理 |
|---|---|---|
| 鼠标移动箭头 | 没有 | 花朵下方半透明方向箭头；面板/控制台/死亡时不画；可关闭 |
| 伤害数字 | 没有真实伤害数据链 | 新增服务端真实伤害反馈包，客户端浮起、轻微放大、渐隐 |
| 普通/毒/雷电数字颜色 | 没有 | 普通暖红、中毒紫、雷电浅黄 |
| 群体命中表现 | 缺少飘字，历史滤镜方案昂贵 | 服务端按目标和类型合并；每包最多 64 项，客户端最多 96 个文字实例 |
| 生物受击颜色 | 白色剪影 | 缓存暖红色剪影，仍只做位图叠绘，无每实体 filter |
| 掉血残影 | 只有绿色血量 | 短暂保留红色旧血量，再平滑追赶；世界/头像共用 |
| 巨型怪物的名牌 | 字号已封顶，但条宽仍随半径无限增大 | 条宽封顶 105px，条与身体间距封顶，保留细血条与稀有度彩字 |
| 地上卡片姿态 | 完全正立 | 小幅、低频倾斜摆动；拾取消失仍保留统一旋转缩小 |
| 换槽动画实现 | 每帧写 left/top/width/height | 改为 translate + scale，保留用户指定的“不旋转” |
| 物理接触/近中心慢走 | 上轮已补 | 保留；本轮不再修改碰撞规则、移动速度或命中伤害 |
| 翅膀、腿、投射物 | 已有按时间/运动幅度的动画 | 保留现有逐部件动画，不凭录屏重新修改服务器尺寸和攻击频率 |

观察点：2:30–7:50、8:30–10:50。伤害值来源是已通过减伤等处理后的服务端健康伤害（Dummy 使用其真实统计命中量），不是血量百分比估算；不会为凑参考文字制造伤害。实际伤害结算逻辑未改。

## 明确未冒充“已经相同”的内容

- 商城、好友/社交、赛季/成就入口、第三方社区链接：FBT 没有对应后端功能，不添加假入口。
- 任务卡：按用户之前明确要求，不做。
- stack/non-stack 矩阵组织：按用户之前纠正，它是显示模式而非缺陷，不改。
- 不同地图的实际布局、敌群组成、稀有度分布、掉落数量、未实现的花瓣/生物：内容/玩法差异，本次不改造服务器玩法来模仿录屏现场。
- florr 的完整皮肤系统、服务器精准击杀事件、服务器远端独立眼神数据：当前没有完全同等信息；远端眼神只能用已收到的方向。
- 本片没有新的清晰 Boss 顶条操作、所有皮肤及全部装备状态，不能据此量化它们的所有动画。

## 验证与交付

- 不启动用户的游戏/浏览器/账号，不修改数据库与部署包。
- 静态语法、依赖棘轮、三语言键、HTML/CSS、离线状态/几何/协议检查。
- 服务端仅补视觉事件数据，需一起更新服务器和网页到 **1.0.3**；旧客户端不能解析新事件，版本握手会明确拒绝。
- 真实运行时帧率、录屏像素级复现及手感仍须用户实机复核，不能用语法检查代替。
